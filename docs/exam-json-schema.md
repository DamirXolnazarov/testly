# Exam JSON Contract

This is what an admin uploads/pastes (or, eventually, what `examGenerator.js`
produces), what `examValidator.js` checks before saving, what the student UI
(`IELTSCDReplica.jsx`) renders, and what `grader.js` scores against. All four
must agree on this shape — this doc is written directly against the current
code, not aspirationally.

A ready-to-use example covering every question type (including audio and a
map) is at `frontend/public/docs/sample-exam-template.json` — download it
from the admin dashboard's "New exam" modal, or copy it directly.

**Two versions of every exam exist:**
- **Full JSON** (server-side, in the database) — includes every `answer` field.
- **Student JSON** (sent to the client) — same shape, all `answer` fields and
  listening `transcript`s stripped by `stripAnswerKeys()` in `routes/sessions.js`.
  This happens server-side automatically; you never write this version by hand.

## Top level

```jsonc
{
  "title": "IELTS Academic Mock Test 12",
  "sections": [ /* one or more of: reading, listening, writing */ ]
}
```
`examId`, `startCode`, `status`, timestamps — all generated by the backend on
creation (`store.js`). Don't include them in what you upload.

## Reading sections

```jsonc
{
  "type": "reading",
  "durationMinutes": 60,
  "parts": [
    {
      "id": "r-part1",
      "title": "READING PASSAGE 1",
      "passage": ["Paragraph one text...", "Paragraph two text...", "..."],
      "instructionsTitle": "Questions 1-3",
      "instructions": "Choose TRUE if...",
      "questions": [ ]
    }
  ]
}
```
`passage` is a flat array of paragraph strings. Multiple `parts` render as
Part 1/2/3 tabs with independent question numbering carried through the
bottom navigator.

### Question types (inside questions[])

Every question needs `id` (unique string), `n` (question number, integer,
unique within its part), and `type`.

**tfng** — True/False/Not Given. `answer` must be exactly `"TRUE"`,
`"FALSE"`, or `"NOT GIVEN"`.

**mcq** — multiple choice. Needs `options` (array of strings). `answer`
must be one of the exact strings in `options`.

**gap-fill** — inline blank inside a sentence, using `before`/`after` text
fragments around the blank. `answer` can be a string or an array of
accepted variants.

**matching** — pick a letter from a shared option bank. Give every question
in the matching group the same `options` array (same text, same order) —
the UI shows the bank once per group and only re-shows it if `options`
changes between consecutive questions.

**table** — fill-in-the-blank table. Has `table.headers`, `table.rows`
(a fillable cell is a literal placeholder string like `"___GAP9___"` that
must appear verbatim somewhere in `rows` — the validator checks this), and
`gaps` (an array mapping each marker to its own `{ id, n, cellMarker,
answer }`). A table question can have several gaps under one question id.

**map** — click a numbered pin, type the label. Has `imageUrl` and `points`
(an array of `{ id, n, x, y, answer }`, where `x`/`y` are percentages 0-100
of the image's width/height for pin placement). Like table, each point has
its own `n` and `answer`.

**Current limitation, stated plainly:** mcq, tfng, matching, table, and map
only render inside reading-type parts right now — the Listening module only
understands the flat items/lines shape below, not the generic question-type
switch. If you want a map question in a real exam, put it in the reading
section (as the sample template does) until Listening is extended to use
the same generic renderer.

## Listening sections

```jsonc
{
  "type": "listening",
  "durationMinutes": 10,
  "parts": [
    {
      "id": "l-part1",
      "title": "Phone call about second-hand furniture",
      "instructions": "Complete the notes. Write ONE WORD AND/OR A NUMBER for each answer.",
      "audioUrl": null,
      "transcript": "Full script here",
      "items": [
        {
          "label": "Dining table:",
          "lines": [
            { "pre": "-", "n": 1, "post": "shape", "answer": "round" },
            { "pre": "-", "text": "medium size" },
            { "pre": "-", "n": 2, "post": "old", "answer": "5" }
          ]
        }
      ]
    }
  ]
}
```
A line with `n` renders an input box (`pre` text, then the blank, then
`post` text) and needs an `answer`. A line without `n` (just `text`) renders
as static text.

**Audio, concretely:** `audioUrl` is a plain hosted MP3/audio URL — nothing
fancier. Until `ttsService.js` (ElevenLabs) is wired up, leave it `null`;
the Listening module detects this and runs a 20-second timed simulation
instead of real playback, so you can test the full flow (pre-play gate,
"Audio is Playing" state, answer inputs enabling) without a real file.
Once you have a real audio host, just put its URL here.

## Writing sections

```jsonc
{
  "type": "writing",
  "parts": [
    { "id": "w-task1", "instructions": "You should spend about 20 minutes on this task. Write at least 150 words.", "prompt": "...", "minWords": 150, "chartImageUrl": null },
    { "id": "w-task2", "instructions": "...", "prompt": "...", "minWords": 250 }
  ]
}
```
Writing is never auto-graded — `minWords` only drives the word-count color
(amber under the minimum, green once met), it doesn't block submission.

`chartImageUrl` is optional and only meaningful for a Task 1 prompt that
describes a chart/graph/table/diagram — Task 2 (essay) parts should simply
omit it. When set, the student's Writing screen shows the real image instead
of the built-in demo chart. Same matching convention as map questions and
listening audio: via zip upload, name the file after the part's `id` (e.g.
`w-task1.png`); via the manual paste/JSON flow, use the "Attach media" panel.
Leave it unset/null and the demo chart shows instead — useful for testing the
UI without a real chart image ready yet.

## Grading contract
- Reading/Listening: auto-graded by grader.js — case-insensitive, trimmed,
  punctuation-insensitive exact match against `answer` (or any entry in
  `answer` if it's an array). Raw score converts to an IELTS band via a
  standard 40-question conversion table, scaled if your paper isn't
  exactly 40 questions.
- Writing: never auto-graded. Admin manually enters Task 1/Task 2 band
  scores into the same Google Sheet row after review.
- Speaking: not built — admin manually adds a band score to the sheet.

## ZIP upload (one file, JSON + media together)
`POST /api/exams/upload-zip` accepts a single `.zip` containing your exam
JSON plus its media files, and attaches each file automatically — no manual
URL copy-pasting, no per-slot clicking. The admin dashboard's "New exam"
modal has an "Upload ZIP" tab that wraps this.

**The matching rule is simple and explicit:** each media file's name
(without extension) must exactly equal the `id` of the thing it belongs to.
- A listening part with `"id": "l-part1"` needs a file named `l-part1.mp3`
  (or `.wav`) in the zip.
- A map question with `"id": "r10"` needs a file named `r10.png` (or `.jpg`/`.webp`).

There's no fuzzy matching or filename guessing — a file named anything else
is reported back as unmatched rather than silently attached to the wrong
place. If any required slot has no matching file, the exam is still created
(so JSON work is never lost) but forced into `draft` status regardless of
what the JSON's own status says, so an incomplete listening section can
never accidentally go live.

This path exists for manually-built/testing exams. Once `examGenerator.js`
is wired to call ElevenLabs during AI generation, the AI writes each part's
`audioUrl` directly — the zip/attach flow becomes unnecessary for that path.

## Validation
Every exam is checked by examValidator.js on both create (POST /api/exams)
and edit (PATCH /api/exams/:id when sections changes) — a malformed
question (missing answer, a matching question with no options, a table gap
whose cellMarker doesn't actually appear in the table) is rejected
immediately with a specific error list, not silently saved to break later
mid-test.

## Google Sheet row shape (one row per completed test)
student_name, exam_id, exam_title, date, reading_raw, reading_band,
listening_raw, listening_band, writing_task1_band, writing_task2_band,
speaking_band, overall_band, status
